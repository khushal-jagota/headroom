# Reviewed implementation plan

1. **Managed-file contract and route.** Add `planner.files/contracts.py`, dependency-free `logic/paths.py`, and `api.py`. Derive the root from the configured database parent so the default is `data/files/tickets`. Validate ticket IDs and already-decoded relative paths; reject empty/absolute paths, dot segments, backslashes, residual or double-encoded separators/traversal, directories, non-regular files, and symlink escapes. Resolve root and target with `Path.resolve(strict=True)` and prove containment with `relative_to`, never string prefixes. Tests cover nested paths, spaces, missing files, `%2e%2e`, `%2f`, `%5c`, `%252e%252e`, directories, and symlinks.
2. **Safe response policy.** Serve through `/files/tickets/<ticket_id>/<path>` with `X-Content-Type-Options: nosniff`. Only an explicit raster-image/audio/video allowlist may be inline. HTML, HTM, SVG, Markdown, unknown, and every non-allowlisted type use `Content-Disposition: attachment`; the filename comes only from the resolved `Path.name`. Browser `fetch` may still read Markdown/HTML for Panels preview.
3. **One reusable frontend contract.** Define a public discriminated `FilePreviewTarget` (initially `ticket-file` and ordinary external link) plus one `resolvePreview` function that owns every extension/type decision. Build one `FilePreview` component consumed in embedded and full modes. New surface kinds extend the target union; no surface branches on extension or MIME.
4. **Explicit hash-preview route.** Use `#/preview?source=ticket&ticket=<encoded>&path=<encoded>`, parse with `URLSearchParams`, decode exactly once, and pass the target contract to `FilePreview`. Cover nested paths and spaces. Markdown is fetched as text and rendered through the hardened Markdown renderer. HTML is fetched as text, assigned only via the iframe `srcdoc` property, never `innerHTML`, and rendered in an iframe with an empty sandbox (no scripts, no same-origin). E2E proves an inline script cannot mutate the parent.
5. **Read-only versus editable Markdown.** Hydrate file previews only from read-only `MarkdownBlock`. Editable Markdown keeps ordinary anchor DOM and the existing serializer, so preview figures/media/iframes never enter a `contenteditable`. Add focus/no-op/save/reopen coverage for Markdown, image, HTML, and unknown-file links; raw Markdown must survive unchanged.
6. **Shared-surface integration.** Have read-only `MarkdownBlock` delegate recognized file links to the public preview component and route every persisted chat message body through `MarkdownBlock`. Cover representative ticket field/proposal/result and chat links, inline image/video, Markdown preview, sandboxed HTML, external link, and download fallback. Exercise every completed slice in a running browser before proceeding.
7. **Closeout.** Document the folder/URL convention, database text versus standalone files, response policy, and reusable preview contract. During implementation run only focused tests and frontend checks. After integration, the integrator performs Codex diff review, resolves findings, live browser verification, rebuilds `web/dist`, and runs the one canonical `./verify`.

## Scope exclusions

No upload UI/API, database artifact/file rows, global registry, file IDs, permissions, comments, PR dashboard, per-stage slots, or broad metadata.
