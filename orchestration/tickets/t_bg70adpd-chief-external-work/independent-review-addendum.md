# Independent dispatch review addendum

A read-only reviewer found four remaining points after the Codex plan review. Their disposition is binding for integration review.

1. **Authority is an operational role boundary, not a security boundary.** Panels is a local, same-user system. `PLAN_ACTOR` and `X-Plan-Actor` prevent ordinary Chief/worker code paths from confusing their roles; they are not tamper-resistant credentials against a worker that deliberately rewrites its environment or HTTP headers. Do not add secrets, authentication, or a new provenance subsystem in this ticket. State this limitation plainly in the owning docs/decision. The promised no-bypass behavior means the worker gateway stays attributed, normal worker guidance says never invoke `panels chief`, Chief CLI calls do not synthesize Chief identity, and the server rejects non-Chief requests in normal use.
2. **Prove production wiring.** Add a focused `create_app`/lifespan construction test that captures the two `SharedGateway` `base_env` mappings. It must prove worker=`PLAN_ACTOR=worker`, Chief=`PLAN_ACTOR=chief`, and preservation of an unrelated environment value.
3. **Lock safety checks with the write.** Pending proposal, ticket control status, and running-turn checks must execute after `BEGIN IMMEDIATE` and in the same transaction as reconciliation. Add a focused competing-writer regression proving reconciliation cannot pass a stale pre-lock safety read.
4. **Prove exact events including aggregates.** Ticket-local field events are ordered `success`, `approach`, `plan`, `result`; `state_changed` and `scope_changed` use cause `external_work`. Existing `_apply_decision` and `_write_ticket_status` must preserve `item_children_changed` events on a parent sprint item for created, state, and ticket-status changes in the same transaction. Add a parented create/reconcile event test rather than introducing a new event kind.
