Verdict: **not ready for implementation**. The plan cannot support t_tt02x’s required data-layer probe drive while keeping `Ticket.state` and `Ticket.ceiling` enum-typed.

## Findings

### [P0] (confidence: 10/10) The row model blocks probe at creation, and several later `.value` calls are missed

The plan explicitly keeps both fields as `TicketState` and defers widening ([plan.md:284](</Users/khushaljagota/.hermes/planning-v2/orchestration/tickets/t_tt02b-generic-field-storage/plan.md:284>)):

> `Ticket.state`/`Ticket.ceiling` remain `TicketState`-typed

That contradicts t_tt02x, which requires `create_ticket(ticket_type="probe")` followed by real data-layer propose/accept operations ([BRIEF.md:37](</Users/khushaljagota/.hermes/planning-v2/orchestration/tickets/t_tt02x-probe-fixture/BRIEF.md:37>)).

Concrete first failure:

1. Probe’s default ceiling is `"needs_alpha"`.
2. `create_ticket` writes that definition-derived ceiling ([data.py:326](</Users/khushaljagota/.hermes/planning-v2/src/planner/tickets/data.py:326>)).
3. It immediately reloads the row ([data.py:351](</Users/khushaljagota/.hermes/planning-v2/src/planner/tickets/data.py:351>)).
4. `_row_to_ticket` executes `ceiling=TicketState(row["ceiling"])` ([data.py:84](</Users/khushaljagota/.hermes/planning-v2/src/planner/tickets/data.py:84>)).
5. Result: `ValueError: 'needs_alpha' is not a valid TicketState`.

So probe never reaches `file_proposal`.

If that load failure were patched locally, the next transition would still fail. `_state_change` calls `.value` on both states ([resolution.py:36](</Users/khushaljagota/.hermes/planning-v2/src/planner/tickets/logic/resolution.py:36>)). Accepting kickoff advances to bare string `"needs_alpha"`, producing:

```text
AttributeError: 'str' object has no attribute 'value'
```

The plan’s T5 test exposes the type contradiction itself: it proposes a `Ticket` with foreign string state/ceiling despite the contract remaining enum-typed ([plan.md:552](</Users/khushaljagota/.hermes/planning-v2/orchestration/tickets/t_tt02b-generic-field-storage/plan.md:552>)). `FieldName("alpha")` in the same test outline is impossible; using bare `"alpha"` then hits unconverted `field.value` calls ([resolution.py:129](</Users/khushaljagota/.hermes/planning-v2/src/planner/tickets/logic/resolution.py:129>), [resolution.py:135](</Users/khushaljagota/.hermes/planning-v2/src/planner/tickets/logic/resolution.py:135>)).

Recommendation: widen the honest domain contract in t_tt02b:

- `Ticket.state: str`
- `Ticket.ceiling: str`
- `Decision.new_state: str | None`
- State/ceiling/field parameters on the generic resolution and admission paths to `str`
- `_state_change(old: str, new: str, ...)`
- Data-layer proposal/accept field parameters to `str` internally
- Convert payload and persistence serialization to `str(...)`

Coding callers remain valid because `TicketState` and `FieldName` are `StrEnum` subclasses of `str`.

Keeping enum annotations while placing bare strings in them is untenable under strict mypy. In particular, overload selection would falsely infer that `advance_target(ticket.state)` returns `TicketState`, even when the runtime object is a probe string.

### [P1] (confidence: 9/10) Prefix derivation assumes an invariant the registry does not enforce

The plan derives `expected_count` from the target state index, but iterates `field_ids(defn)` as the prefix order ([plan.md:368](</Users/khushaljagota/.hermes/planning-v2/orchestration/tickets/t_tt02b-generic-field-storage/plan.md:368>), [plan.md:373](</Users/khushaljagota/.hermes/planning-v2/orchestration/tickets/t_tt02b-generic-field-storage/plan.md:373>)).

The registry guarantees every field is gated exactly once ([validation.py:113](</Users/khushaljagota/.hermes/planning-v2/src/planner/ticket_types/logic/validation.py:113>), [validation.py:126](</Users/khushaljagota/.hermes/planning-v2/src/planner/ticket_types/logic/validation.py:126>)), but it does **not** require declared field order to equal stage gate order.

Concrete failing definition, valid under current validation:

```text
stages: needs_kickoff(kickoff) → needs_alpha(alpha) → needs_beta(beta) → done
fields: kickoff, beta, alpha
supports_prefix_reconciliation: true
```

Reconcile to `needs_beta` yields `expected_count == 2`, then requires `kickoff` and `beta`, while forbidding `alpha`. The correct settled stage prefix is `kickoff` and `alpha`. This silently validates the wrong fields.

Recommendation: derive the reconciliation order from non-terminal stages’ `gating_field` values, not from `field_ids(defn)`. That uses the already-enforced one-to-one gate model and introduces no new registry invariant.

The plan does require parity against the old coding map before deleting it ([plan.md:627](</Users/khushaljagota/.hermes/planning-v2/orchestration/tickets/t_tt02b-generic-field-storage/plan.md:627>)), so point 2(a) is conceptually covered. But it is absent from named tests T1–T6. Make it a permanent golden test asserting the exact coding mapping:

```text
needs_success: 1
needs_approach: 2
needs_plan: 3
needs_implementation: 4
needs_closeout: 5
done: 6
```

“Confirm before deletion” is an implementation instruction, not lasting regression protection.

Boundary ruling: threading `definition=` and replacing prefix semantics are separable. The cleaner boundary is:

- t_tt02b: add explicit definition threading and retain an explicit coding-only reconciliation boundary.
- t_tt03: replace `_FIELD_ORDER`/`_PREFIX_COUNT`, widen external-work ingress, honor `supports_prefix_reconciliation`, and test probe external-work end-to-end.

That matches t_tt02x’s explicit exclusion of external-work ([BRIEF.md:47](</Users/khushaljagota/.hermes/planning-v2/orchestration/tickets/t_tt02x-probe-fixture/BRIEF.md:47>)). If external reconciliation remains in t_tt02b, it must be completed fully rather than only replacing the two tables.

### [P1] (confidence: 10/10) Definition threading is incomplete for the behavior the plan claims

The plan deliberately leaves direct scope change coding-defaulted ([plan.md:414](</Users/khushaljagota/.hermes/planning-v2/orchestration/tickets/t_tt02b-generic-field-storage/plan.md:414>)). `file_proposal`, `accept_proposal`, `decide_edit_value`, `decide_return_for_revision`, and `plan_handoff_status` are otherwise identified for correct per-row threading.
