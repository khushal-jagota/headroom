# ACP-11 — Native worker-role skills and ACP kickoff

## Owner decision

Panels-owned skills are installed in every supported backend's native project skill location. Each
new ACP conversation adds its employee role to whichever real prompt arrives first, whether that
prompt was typed by the user or generated by Automatic Employee work. Ticket conversations invoke
`panels-worker`; the Chief invokes `panels-chief-of-staff`. Later prompts in the same conversation are
untouched. Claude no longer receives a Panels-specific system-prompt append. The Hermes checkout
remains read-only.

## Public seams

1. The repository's canonical `skills/` directory is exposed through both native project roots:
   `.agents/skills` for Codex and `.claude/skills` for Claude. The links resolve to the same repository
   source, so every current and future Panels skill is available without a second registry or copy.
2. Existing Hermes startup provisioning continues to expose the same canonical skill sources under
   the configured Hermes home.
3. A successful ACP `session/new` arms exactly one role kickoff for that new session. The first
   `session/prompt` delivery prepends `Use the installed \`panels-worker\` skill.` for a Ticket employee
   or `Use the installed \`panels-chief-of-staff\` skill.` for the Chief. The first prompt may originate
   from the browser or Automatic Employee work. A text-only ACP command whose first block starts with
   `/` passes through unchanged and leaves the role armed for the next ordinary prompt. A failed replacement
   `session/new` preserves the prior session's arm. Later ordinary prompts, session loads, compaction
   forks, and replacement children for the same durable conversation do not re-arm it. Starting New
   conversation does after `session/new` succeeds.
4. Panels-visible human text stays equal to the text the user or Automatic Employee supplied. The
   role directive is delivery context, not text attributed to the human, including after typed replay.
   Echo normalization is temporary, scoped to the exact session prompt or replay operation, and
   consumes only one synthetic role echo. It preserves a legitimate prompt equal to the directive and
   handles both a separate directive chunk and Hermes' flattened `directive + "\n" + original` echo.
5. Claude `session/new` and `session/load` requests preserve caller metadata without adding or
   reserving `_meta.systemPrompt`. Claude-specific compaction normalization remains unchanged.

  child containing `SKILL.md`.
- Decorator unit tests and official-SDK e2e assertions prove the exact role directive reaches only the

  while compaction normalization still passes.
