What changed, and why

Each note keys to something visible on the left. IDs match nothing in the codebase — they're for this conversation.

R1

A silent header: identity left, budget right

Left, just the worker's name. Right, usage_update as "x / y · cost". Liveness lives in the thread (shimmering thought, step spinner, send→Stop), so the header only ever speaks when the thread can't: "waiting for you", "compacting" — silence otherwise. Connection trouble is a single red dot that appears left of the name (see Offline); failure says nothing here — the centred pill in the thread is the whole signal.Was: binary dot + status line + raw "41200 / 200000 tokens" string; drafts with a meter bar and a backend name were cut on review.

R2

Tasks are a pill above the composer

While a turn is active, a centred pill in its own reserved strip between thread and composer reads "2 / 5 tasks" — a spinner joins it when something is actually running (not while waiting on you). The x/y is honest because the plan arrives as a complete list. Hovering reveals the tasks with their states: ✓ done, › in progress, ○ pending. The strip is in-flow — space stays reserved in every state, nothing floats over the chat.Was: the plan as an inline list wherever it arrived; a pinned-header draft was cut earlier in review.

R3

Timestamps — dropped

First draft added turn-separator clocks and hover timestamps; cut on review. The panel stays timeless, as it is today.

R4

Thinking earns a preview

Collapsed thought is the word plus its first line in italic serif — nothing else; while streaming, the word "Thinking" shimmers. Expanding reveals the full reasoning and the steps.Was: the bare word "Thinking", identical whether live or settled. Draft versions carried a duration and step count on the line; cut on review.

R5

Tool calls nest inside the thought that drove them

While a turn runs there is always exactly one live "Thinking" line — even on runtimes that emit no thought text. Thought text attaches to it as it streams; a new burst of thinking starts the next stanza. The tool calls are truly nested: collapsed, a stanza is one line ("Thought · preview · 11s · 4 steps"); expanding it reveals the full reasoning and the steps beneath, each with its kind glyph, ✓/✕/spinner mark, and +/− counts on edits. Steps expand further into their diff or output, and a failed stanza arrives pre-expanded so the ✕ is never buried. No borders or insets — nesting is expressed by disclosure, not indentation.Was: identical always-visible cards reading "execute · in_progress", detached from the reasoning above them.

R6

Compaction is a visible seam, live and settled

While it runs (a real state — the server emits compacting both as activity and on the compaction item), the divider shimmers "context compacting" and the header says compacting, since nothing else on screen moves. Settled, it reads "context compacted · automatic" — honest about where history was condensed, using only what the wire carries.Was: a one-line whisper indistinguishable from other markers.

R7

Permission choices carry weight

Borderless accent surface. Reject sits left as a ghost that only turns red on intent; the allow options gather right, ending on the filled primary Allow — the eye lands where the common action is. Labels and option count come from the server ({id, label, kind}); the kinds (allow/reject × once/always) drive the weighting. The countdown shows the wire's deadlineAt.Was: bordered box, four identical outline buttons in server order, no deadline.

R8

Send and Stop are one control

While a turn runs, the send arrow becomes a bordered red ■ Stop in place. Delivery choice (queue / send now / steer) compresses into a small segmented control in the composer footer, present only mid-turn; steer greys out on backends that can't.Was: separate Stop and New conversation outline buttons below; a row of three toggle buttons above the box.

R9

The queue grows out of the composer

Queued prompts are a tray fused to the top of the sending box — same recessed surface, slightly inset, corners merging into it — so they read as "already in the box, waiting their turn". The sending box keeps its own full rounding; the tray tucks behind it. Numbered rows, each with its own ×.Was: a plain list with "Cancel" buttons above the composer, plus bare "queued · queue 2" markers in the transcript. A chips draft followed; replaced by the tray.

R10

Turns end honestly

When a turn ends any way other than normally, a centered chip says so — "turn failed · 1 test failing", "hit token limit", "interrupted" — using the stop reason the server already knows.Was: single mono words ("interrupted") floating contextless in the thread.

R11

Destructive actions step back

"New conversation" leaves the composer for an overflow menu with a confirm — it wipes the thread and shouldn't live one pixel from Stop. Delivery/system markers leave the transcript entirely; their information moves into the chips, chips' states, and turn-end chips.Was: thread littered with accepted / started / queued mono lines.

R12

Wire exceptions are quiet pills

A protocol rejection (backend sent something outside the pinned schema) is a centred red-outline pill — "unsupported update" — that reveals the server's reason on click (see Failure). Unsupported content items get the same treatment. Raw tool input/output and the permission "submitting" state are dropped entirely.Was: a red-bordered mono line inline for rejections, faint "Unsupported agent content" lines, a raw I/O disclosure per tool card.
